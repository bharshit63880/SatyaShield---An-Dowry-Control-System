# Security Policy

SatyaShield handles workflows that may involve sensitive information. Please report suspected vulnerabilities privately and responsibly.

## Supported version

Security updates are applied to the latest revision of the `main` branch. Historical commits and forks are not supported releases.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting feature for this repository when available. Do not open a public issue containing exploit details, credentials, secrets, personal information, complaint content, evidence, or exact locations.

Include:

- A concise description of the vulnerability.
- The affected component and revision.
- Reproduction steps using synthetic data only.
- The expected and observed behavior.
- The potential security or privacy impact.
- A suggested mitigation, if known.

Please allow reasonable time for triage and remediation before public disclosure. Do not test against real users, real cases, third-party organizations, or infrastructure you do not own or have explicit permission to assess.

## Scope notes

The public deployment is a restricted demonstration and internal-evaluation environment. It is not approved for real complaints, NGO casework, legal services, or emergency response. Reports about missing real-world dispatch or disabled external integrations are not security vulnerabilities unless they demonstrate a bypass of an intended safeguard.
